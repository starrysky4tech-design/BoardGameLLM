# 要求内容

## 概要

Monopoly の実機操作(`plugins/monopoly/vision/` と `runtime.py`)に散らばった、画面遷移の重複を共通化する。
外から見た動作(送る入力の並び、止める条件)は変えない。

## 背景

2026-11-11 の重複調査で、次の重複が見つかった。実装ごとに挙動が少しずつ違い、片方だけ直した不具合が残りやすい。

- 「盤の通常の画面へ戻る」が 6 実装(試行回数、通知ダイアログの扱い、色の確認、取引画面の扱いが、ばらばら)
- 「色グループを開く → 案内を消す → 画面を確かめる」が 5 箇所(案内のタップが通知を出したときの対処は 1 箇所だけ)
- 家を建てる `build_group` と、家を売る `sell_houses` が、押す位置と順序を除いて同じ
- 刑務所の確認待ち(`pay_bail`、`pay_bail_top`、`use_jail_card`)の後半が同じ
- 盤の画面名の組、通知の OK の座標(5 箇所)、詳細画面の Return の座標(3 箇所)、待ち秒、`_fail` が複数のファイルにある

## 実装対象の機能

### 1. 画面遷移の共通部品(手順 1)

- `vision/navigation.py` を新設し、「盤へ戻る」と「色グループを開く」を 1 つずつにする
- 盤の画面名の組、通知の OK の座標、建設画面の y、待ち秒、失敗の結果を作る関数を、1 箇所に集める
- 既存の 6 + 5 箇所を、共通部品の呼び出しに置き換える

### 2. 操作の共通化(手順 2)

- `build_group` と `sell_houses` を、1 つの内部関数にまとめる(公開する関数の名前と引数は変えない)
- 刑務所の 3 操作の「押す → 確認を待つ → Yes」を、1 つの内部関数にまとめる

## 受け入れ条件

### 画面遷移の共通部品
- [ ] 「盤へ戻る」の実装が `navigation.return_to_board` の 1 つだけになる(`runtime._return_from_improvements` は、確認ダイアログで止める別の役割なので残す)
- [ ] 「色グループを開く → 案内を消す」の実装が `navigation.open_group` の 1 つだけになる
- [ ] 通知の OK の座標 `Point(1254, 811)` の定義が 1 箇所になる
- [ ] 盤の画面名の組の定義が 1 箇所になる
- [ ] `read_group_houses` の画面の取得回数が増えない(既存のテスト: 1 色グループあたり 5 回以内)

### 操作の共通化
- [ ] `builder.build_group` と `property_manager.sell_houses` が、同じ内部関数を呼ぶ
- [ ] `pay_bail`、`pay_bail_top`、`use_jail_card` が、同じ内部関数を呼ぶ

### 全体
- [ ] `.\scripts\check.ps1` が通る(ruff、mypy、lint-imports、pytest)
- [ ] 実機で、状態を変えない操作(色グループを開いて戻る、家の数を読む)が、変更前と同じに動く

## 成功指標

- 対象 5 ファイル(builder、holdings、property_manager、executor、runtime)の重複した実装が減る
- 既存のテストが、期待値を緩めずに通る(挙動を揃えた箇所は、理由を書いてテストを直す)

## 前提・仮定

- 実機の検証は、対局の状態を変えない操作に限る — 根拠: 建設・売却・抵当・保釈は、所持金を減らす(売却は半額、抵当の解除は利息 10%)。これらは偽の入出力のテストで確かめ、実機では次の自動実行で確かめる
- 取引画面を Cancel で閉じる処理は、土地の管理(`property_manager`)からの呼び出しだけで有効にする — 根拠: 現在の実装がそうなっている。他の経路で取引画面を閉じると、AI の提案を断る操作と紛れる
- `ownership.read_owner` は残す — 根拠: 本番の経路では使っていないが、削除は今回の範囲(推奨順 6)ではない

## スコープ外

以下はこのフェーズでは実装しません:

- `logic/` 側の重複(色グループの集計、位置の辞書、盤の定数。調査の B1〜B5)
- `runtime.py` の重複(抵当の旗の修正、現金の補正。調査の C)
- 旧系統のモジュールの削除(調査の D)
- 待ち秒の短縮などの高速化
