# 要求内容

## 概要

Monopoly の画面から、自分と AI の所持金を、人の入力なしで読む。読めないときは「不明」を返し、値を埋めない。
自律対局の3計画の1番目(2: Log の読み取り `20261102-monopoly-log-reader`、3: 実機を動かす層 `20261102-monopoly-runtime`)。

## 背景

- 本番は Python だけで自律的に対局する(memory `monopoly-operating-model`)。所持金は、購入・入札・建設・取引のすべての判断の入力で、読めなければ `logic` の方針が動かない
- Phase 0 で、所持金の機械読み取りは不安定と判断した(桁がつながる、細い数字が割れる)。その間は、人が読み上げて記録した(`RESULT.md`「運用(一時的)」)。これは設計上の前提ではない
- 2026-11-01 の手動対局(104 手番)で、所持金の取り違えが 5 回起きた(第 21・41・44・89・99 手番)。原因は主に、盤の所持金表示の更新が遅れることと、GO 通過の +200 が Log に出ないこと
- 所持金の表示は、画面上部中央の固定位置(左が自分、右が AI)。アニメーションは Off にしてある

## 実装対象の機能

### 1. 所持金の読み取り(`vision/cash.py`)
- 画面(2432x1080)から、自分と AI の所持金(整数)を読む。値と信頼度を返す
- 数字は、1 桁ずつ切り出して 0〜9 のテンプレートで読む。切り出せない、桁数が想定外、信頼度が閾値未満のときは「不明」
- 表示の更新途中(桁が変わる途中)を読まない。間隔を置いた 2 枚が一致したときだけ採用する

### 2. 読み取りの評価
- ラベル付きの評価セット(`datasets/eval/monopoly/cash/`、Git 管理外)を作り、誤読 0 を確かめる
- テンプレートの切り出し元と、評価に使う画像を分ける(Phase 0 の画面判別で残った課題)

## 受け入れ条件

### 所持金の読み取り
- [ ] 評価セット(2 局以上、桁数 1〜4 桁以上を含む)で、誤読が 0 件
- [ ] 不明は許容するが、評価セットの 5% 以下
- [ ] 同じ画面を 2 回読んで一致する
- [ ] 表示が更新途中の画像で、誤った値を返さない(不明を返す)
- [ ] `logic/` が `vision/` を import しない(`lint-imports`)

## 成功指標

- 誤読 0 / 評価セット全件
- 1 回の読み取り(自分と AI の両方)が 100 ms 以下(GPU を使わない。docs/03 の資源配分に収める)

## 前提・仮定

- 位置と色は、2432x1080 の実機解像度で固定 — 根拠: `RESULT.md`「所持金の表示」(位置は固定)、Kahuna の `screens.py`
- 負の所持金(破産処理の途中)の表示は、評価セットに出たときだけ扱う。出なければ「不明」とする — 根拠: 破産時の画面は未収集(`RESULT.md` 未確認)
- 評価セットのラベルは、画面を見て手で付ける(実装の出力は使わない) — 根拠: CLAUDE.md「期待値は実装から作らない」
- 読み取り手段は数字のテンプレート照合で進める(ユーザー指示、2026-11-02)。Phase 0 の不安定の原因を切り分けたうえで、桁の分割を作り込む
- 既存の画像: 対局 A の全画面 167 枚(2026-10-31)と、対局 B の 16 枚(2026-11-01)。評価の分離は、対局 A を切り出し用、対局 B を評価用にして行い、対局 B が足りなければ追加で集める — 根拠: `datasets/raw/monopoly/`、`datasets/eval/monopoly/screens/`
- 新規の依存は追加しない。テンプレート照合で足りない場合は、この計画を終えて別計画にする — 根拠: `20261101-monopoly-vision/02_DESIGN.md`「OCR は使わない」と同じ理由。VLM は「数字は読まない」(CLAUDE.md「GPU」)

## スコープ外

- Log の文字の読み取り(計画 2)
- 実機の操作、プラグイン登録(計画 3)
- 所持金の整合検査(取引の前後の差分との照合)。計画 3 の状態追跡で扱う
- OCR・CNN の導入(テンプレート照合が受け入れ条件を満たさなかった場合の、別計画)
