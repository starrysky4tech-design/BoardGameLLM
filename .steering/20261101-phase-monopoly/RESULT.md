# Monopoly Phase 0 結果(実機で確かめた事実)

確認日: 2026-10-31〜11-01 / 端末: SHG11(`355092380222016`、横向き 2432x1080)
素材: `datasets/raw/monopoly/feasibility/`、`samples/`(Git管理外)

## アプリ
- パッケージ `com.eamobile.monopoly_na_wf`、版 04.00.23(versionCode 4000224)、targetSdk 26
- 起動は横向き。タイトルから `PLAY NOW`。課金は発生しないと確認済み。戦績の変化は問題なしと確認済み

## 対局
- Game Setup: 自分(Battleship/Human)、AI(Wheelbarrow)。難易度は Very Easy を選択
- Tutorial 確認は No。先手は AI(Wheelbarrow)
- 盤は3D俯瞰。カメラはターンごとに切り替わり、盤が画面に収まる時と収まらない時がある
- メニュー(左): Roll / End Turn、Trade、Manage、Log、Pause
- 購入は「Buy」→「Yes」の2段階。見送りは「Pass」→「Yes」。オークションは Bid / Pass / Forfeit、入札は数字キーパッドで入力し ACCEPT
- Log は文字で出来事を表示(例: "Battleship rolled 3"、"bought Baltic Avenue for M60")。ただし行の切り出しは背景と混ざり不安定
- アニメーションは OPTIONS で Off にした(所持金の位置は変化なし)

## 所持金の表示
- 画面上部中央。左が自分、右が AI。位置は固定
- 文字の機械読み取り(桁の切り分けと照合)は、桁がつながる・細い数字が割れるため不安定。数字の照合は採用しない

## 運用(一時的。設計上の前提ではない)
- 設計: 所持金を含む状態は、画面から自動で読む(人の入力は前提にしない)
- 上記は、ロジックの精度を上げる作業の間だけの運用。Phase 0 で文字の機械読み取り(所持金の数字、Log の行切り出し)が不安定だったため、その間は所持金を人が読み上げて記録する
- 盤の見た目の読み取りは、精度が未確認のため今は使わない
- 人が読み上げる記録は、所持金だけ(自分と AI の額)。手番、サイコロ、購入、Log の文は入力しない
- 入力方法: 人が所持金を読み上げ、私がその値を記録する。読み上げは「自分 ○○、AI ○○」の形で行う
- 記録先: 1 手ごとに 1 行(連番、自分の額、AI の額)

## 不具合: 自分の手番でロールが反映されない(2026-11-01 対局、保留)
- 対局: Very Easy、Top Hat(Human) 対 Battleship(AI)、チュートリアル No。Top Hat の ST. CHARLES PLACE(₼140)購入まで実施
- 症状: Roll フリック(`input swipe 1257 763 1257 300 120`、遅め版 `300ms` も同じ)で、ダイスが空中で止まる → Roll 表示に戻る。駒と所持金が動かない(Top Hat ₼1370、Battleship ₼1290 のまま)
- Animations Off でも再現。Log 下段は読めず、ロール結果の記録は確認できない
- 1 回目のフリックは反映なし、2 回目でダイスの転がりは見えた。移動は確認できず
- 未確認: 原因(ダイス物理かロール結果の反映か)、フリック以外のロール操作で回避できるか
- 対応: 対局は保留。再試行は、原因が分かるまで行わない(二重ロールと状態不明を防ぐため)

## 解決: ロールは「タッチ → 保持 → 上へ移動」で入力する(2026-11-01 17:33、実機確認)
- `input swipe`(保持なし)は、ダイスは転がるが結果が反映されない
- `input motionevent DOWN/MOVE/UP` で、DOWN 後に 0.6 秒保持してから MOVE を 6 段階で上へ送ると、ロールが反映された(Roll 表示が消え、End Turn が出る)
- 端末側スクリプト `/data/local/tmp/flick_hold.sh`(Git 管理外の scratchpad に原本)。Roll ボタン位置 (1257,763) から (1257,300)
- 手動フリックと同じ「Touch, hold, and flick」の操作になったため、保持が必要だった可能性が高い(推測)
- 未確認: 保持時間の下限、他の座標での再現
