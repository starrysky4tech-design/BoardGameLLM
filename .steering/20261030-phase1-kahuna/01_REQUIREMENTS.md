# 要求内容

## 概要

`docs/01` の Phase 1: Kahuna で、画面取得 → 認識 → ルール → 思考 → 操作 → 確認の一巡を実装し、1ゲームを人手なしで完走できるようにする。共通基盤（F1・F5・F6・F7）とKahunaプラグイン（F2〜F4）を同時に作る。

## 背景

Phase 0 で、Kahuna の画面取得（約1秒）と tap が通り、盤面・手札・場札・杖コマが判別できることを確認した。最初のゲームでエンドツーエンドを完成させ、大戦略SSB2 に先立って共通基盤の設計（`GamePlugin`、`GameIo`、実行ループ）を検証する。

## 実装対象の機能

### 1. 共通基盤の土台（F1、F5、F6、F7）
- データモデルと `Protocol`（`docs/02` の共通モデル）
- Android用の `ScreenSource` と `InputDriver`、`ChangeDetector`
- `GameIo`（実行用とリプレイ用）、`RunLogger`、`Replayer`、`EvalHarness`
- `AgentRunner`、`SafetyGuard`、`PluginRegistry`、CLI

### 2. Kahunaの盤面認識（F2）
- 画面の種類の判別（タイトル、ステージ選択、対戦中、相手の手番、決算、終了、想定外）
- 対戦中の読み取り: 島と点線、杖コマ（自分と相手）、カフナコマ、手札、場札、山札の枚数、ラウンドと得点
- キャリブレーション（島と点線の位置）、デバッグ用の重ね描き画像

### 3. Kahunaのルールと思考（F3、F4）
- ルールページに基づく合法手の列挙、支配判定、決算
- 評価関数ベースの思考（`docs/02` のアルゴリズム設計）

### 4. 実機での自動プレイ
- `step` モードと `auto` モード、緊急停止、停止条件
- 決算・カフナコマ・終了画面の撮影（Phase 0 から持ち越し）
- KPIの計測

## 受け入れ条件

### 共通基盤
- [ ] `docs/02` の `Frame`、`InputAction`、`Recognition`、`StepRecord`、`RunSummary` が実装され、型検査を通る
- [ ] `import-linter` の契約（`docs/04` の依存ルール）が設定され、違反が検出される
- [ ] 録画済みの画像を返す偽の `ScreenSource` で、実行ループが実機なしで動く
- [ ] 全 `StopReason` に対応するテストがあり、停止条件ごとに操作が送られないことを確認できる
- [ ] 緊急停止キー押下後1秒以内に入力が止まる（自動テスト）

### 認識
- [ ] 対戦中の画面で、手ラベル付けした30画面以上に対する要素単位の正答率が95%以上（`bglm eval`）
- [ ] 全体画像を VLM に渡さず、テンプレートマッチングと切り出しで読む（VLMは使わない、または切り出した1要素の分類に限る）
- [ ] 低信頼度のときは `state=None` を返し、既定値で埋めない
- [ ] 想定外画面を `UNKNOWN` として検出できる

### ルールと思考
- [ ] 期待値がルールページの記述から作られたテストで、合法手の列挙、支配判定、決算の得点が検証されている
- [ ] 手札上限5枚、場札3枚などの数値が、アプリの実測と一致している
- [ ] 思考の1手が `docs/01` の「10秒以内」に収まり、思考時間の上限に達したら最善手を返す
- [ ] 思考ロジックのテストが画面・VLMなしで動く

### 実機での自動プレイ
- [ ] `step` モードで1ゲームを人が確認しながら完走できる
- [ ] `auto` モードで1ゲームを人手なしで完走できる
- [ ] 完走率が8割以上（10ゲーム以上で計測）
- [ ] 対CPU戦の勝率が5割以上（同じ10ゲームで計測）
- [ ] 1手あたりの所要時間が平均30秒以内
- [ ] 誤操作率が2%以下
- [ ] 決算、カフナコマ、終了の各画面が撮影され、認識の評価セットに入っている

## 成功指標

- `docs/01` の Phase 1 の完了条件（F2〜F7 の Kahuna 分、認識正答率・完走率・勝率のKPI）を満たす
- 共通基盤に Kahuna 固有の知識が漏れていない（`application` が `plugins` に依存しない）

## 前提・仮定

- 評価するステージは、ステージ選択画面の最初のものから始め、標準難易度のCPU戦が選べるステージを調査して決める — 根拠: `docs/01` の「Kahunaは標準難易度」。ステージ名と難易度の対応は未調査
- 1つ目のステージのチュートリアルは評価に使わない — 根拠: 案内の表示で手順が固定され、通常の対戦と異なる
- 点線の接続関係（島と点線の対応）は、実機の画面から読み取って `board.json` に固定する — 根拠: 盤面は固定で、ルールページに載っていない
- 山札の枚数、手札の上限、杖コマ・カフナコマの個数は、ルールページに記載がないため実測で確認する — 根拠: `docs/01` の「Kahunaのルール」
- 評価の勝敗は、ゲーム内の得点表示で判定する — 根拠: 外部の記録を持たない

## スコープ外

以下はこのフェーズでは実装しません:

- 大戦略SSB2の認識・ルール・思考
- VLM を使う認識の本格的な実装（切り出しで読めない要素が出たときのみ、F8の最小限）
- LoRA学習（F9）
- 数手先の探索（F10）。評価関数の1手選択のみ
- オンライン対戦への対応
