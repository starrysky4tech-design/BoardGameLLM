# 要求内容

## 概要

Android版「Maquis」(Boardnaut Studios)を自動でプレイするプラグイン `maquis` を追加する。Kahuna・Hive と同じ共通基盤(認識 → 思考 → 操作のループ、安全装置、ログ、リプレイ、評価)の上に、`plugins/maquis/` を書き足す形で作る。

## 背景

- Android のボードゲームの自動対戦を増やす方針の4本目(Kahuna、Hive、Monopoly に続く)
- 実機(SHG11)に Maquis が導入済みで、接続手段(adb)をそのまま使える
- Maquis は**1人用**のゲームで、対戦相手はアプリ(山札から置かれる巡回)である。相手の手が「思考」ではなく「山札のめくり」で決まるので、これまでの2人対戦(Kahuna、Hive)とは思考の作り方が違う(確率の期待値で選ぶ)。共通基盤が「予測どおりに盤面が変わる」ことを前提にしていないかを確かめる題材にもなる(`docs/01` のKPI「共通基盤の変更量」)

## 実装対象の機能

### 1. ルールとシミュレータ(`plugins/maquis/logic/`)
- 盤(場所と道)、資源、士気、日数、任務、巡回カードの山札、部屋の建設を持つ状態と、合法手の列挙、勝敗の判定。画面に依存しない
- 山札を乱数で引くシミュレータで、1ゲームを logic だけで完走できる
- アプリが採用する任務・難易度・部屋の組み合わせを設定で切り替えられる

### 2. 思考(`logic/strategy.py`)
- 巡回カードの残り(数え上げ)から、配置ごとの勝率を見積もって1手を選ぶ(第一案: 残りの山札を無作為に並べて打ち切りまで進めるモンテカルロ)

### 3. 認識(`plugins/maquis/vision/`)
- 画面から、各場所の駒(自分、民兵、兵士)、資源の数、士気、日数、任務の進み、残りの人員、ダイアログを読む
- 巡回カードの捨て札(めくられたカード)を追い、山札の残りを状態に持つ

### 4. 操作(`vision/executor.py`)
- 「場所へ人員を置く」「行動を解決する」「隠れ家へ戻る道を選ぶ」などの手をタップに変換し、結果を画面で確認する

### 5. 組み込み
- `config/maquis.toml`、プラグインの登録、`bglm run/eval/replay --game maquis` が動く
- `tests/plugins/maquis/`、必要なら `scripts/maquis/`、`assets/maquis/`、`datasets/{eval,raw}/maquis/`

## 受け入れ条件

### Phase 0(実機で確かめる)
- [ ] パッケージ名、バージョン、座標系(横向き 2432x1080 の取得画像の座標をそのまま `input tap` に渡せるか)が記録されている
- [ ] 無料版で遊べる範囲(任務、難易度、部屋)と、触れてはいけない画面(「完全版を入手」、他ゲームの宣伝、統計のリセットなど)が記録されている
- [ ] 1ゲームを手で最後まで進め、手番の流れ(配置 → 巡回 → 行動 → 帰還)、各操作のタップ手順、終局の表示が記録されている
- [ ] アプリ内の「ルール」を書き起こした `docs/ideas/Maquis_アプリ内ルール.md` がある
- [ ] Go / No-Go の判断が `RESULT.md` にある

### ルールとシミュレータ
- [ ] 配置、巡回カード、逮捕、行動、士気、任務、勝敗の規則を、アプリ内ルールの記述から手で作った期待値で検証している(出典付き。実装から期待値を作らない)
- [ ] 固定シードの自己プレイで1ゲームを完走し、不正な手が出ない

### 認識・操作
- [ ] 手ラベル付けした30画面以上で、要素単位95%以上(KPI。仮)
- [ ] 想定外の画面、信頼度不足、禁止画面では入力を送らず止まる

### 自動完走
- [ ] 1ゲームを人手介入なしで終えられる割合が8割以上(KPI。仮)
- [ ] 勝率(任務を2つ達成して終わる割合)が5割以上(KPI。仮。難易度は Phase 0 で決める)

## 成功指標

- `docs/01` のKPIを、Maquis についても同じ基準で測る
- 共通基盤(`core/`、`application/`、`infrastructure/`、`toolkit/`)の変更行数を数えて記録する。不足を直した分は理由を書く

## 前提・仮定

- 対象は端末 SHG11(シリアル `355092380222016`)の Maquis。パッケージ `org.boardnaut.studios.maquis.android`、versionName 1.10(versionCode 16)、起動 `.AndroidLauncher`、横向き 2432x1080 — 根拠: 2026-11-11 に adb で確認
- 起動画面は「新規ゲーム」「つづきから」(保存が無い間は灰色)「ルール」、下に統計・情報・設定、右上に「完全版を入手」、右下に他ゲームの宣伝がある。表示は日本語 — 根拠: 2026-11-11 の取得画像1枚(操作はしていない。ゲーム中の画面は未確認)
- インストールされているのは**無料版**と見ている。遊べる任務・難易度に制限がある可能性がある — 根拠: 起動画面の「完全版を入手」。範囲は Phase 0 で確かめる
- 「完全版を入手」と宣伝の領域は**禁止画面・禁止領域**とし、押さない。購入はしない — 根拠: `CLAUDE.md`「ユーザーのアカウントに影響する操作は事前に確認する」
- 1人用のゲームなので、オンライン対戦やアカウントの戦績は無いと見ている。アプリ内の統計(勝敗の数)は自動プレイで変わる。**統計が変わってよいかは、Phase 0 の最初の対局の前にユーザーへ確認する** — 根拠: 同上
- ルールの概要(人員を1人ずつ置くたびに巡回カードを1枚めくって民兵を置く。戻る道を塞がれた人員は逮捕。士気が尽きる・人員を全て失う・期限切れで負け。任務を2つ達成で勝ち)は、ボードゲーム版の一般的な知識による**未確認の理解**である。正本はアプリ内ルールとし、Phase 0 の書き起こしの後に logic を作る — 根拠: `CLAUDE.md`「ルールの期待値は実装から作らない」
- 接続手段は adb、アプリを離れるときは HOME キー、`am force-stop` は使わない — 根拠: `CLAUDE.md`「実機の操作」
- `GamePlugin` の形で作る(Monopoly のような独自の実行ループにしない) — 根拠: `docs/04`「スケーリング戦略」。Maquis は1手番に1つの決定で進むため、Kahuna・Hive と同じループに収まると見ている。収まらない点は Phase 0 の後に設計を見直す

## スコープ外

- 完全版の購入と、完全版だけの任務・難易度・部屋
- 最高難易度での勝率の追求。まず完走と、遊べる範囲の標準の難易度での勝率5割を目標にする
- アプリの改造・再署名、保存データの書き換え
- Monopoly、Kahuna、Hive、大戦略SSB2 の作業
