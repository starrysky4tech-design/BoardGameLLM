# 要求内容

## 概要

Monopoly の画面から、出目と、その手番の出来事(止まったマス、支払い、カード、刑務所)を、人の入力なしで読む。読めないものは「不明」を返し、値を埋めない。
自律対局の3計画の2番目(1: 所持金 `20261102-monopoly-cash-reader`、3: 実機を動かす層 `20261102-monopoly-runtime`)。

`20261101-monopoly-vision` の「フェーズ2: 出目と着地の読み取り」を引き継ぐ。あの計画のフェーズ2は、Log の文字を読む方針のまま未着手で止まっている。本計画は、読む情報の取り方を見直してやり直す(下記「方針」)。

## 背景

- 手番を追うには、出目が要る。止まったマスは、前の位置 + 出目で計算できる(カードの移動と刑務所は例外)
- 支払いの額は、所持金の差分(計画 1)から分かる。Log の金額を読まなくてもよい
- Phase 0 と 2026-11-01 の検証で、Log パネルの文字の切り出しは不安定だった。パネルが半透明で、盤の模様と文字が混ざる(輝度の閾値では分けられない)
- 一方、黄色の表示「Battleship rolled 11」は、黄色の画素の抜き出しで、文字ごとに分離できた(19 成分、末尾 2 成分が数字)。数字 0〜9 の見本が足りず、そこで止まった
- Log は、スクロールが反応しない。上段だけ読める。最新行は読めない
- 2026-11-01 の手動対局で、Log の読み違えや、Log に出ない出来事(GO 通過の +200)で、状態を取り違えた

## 方針

読む対象を、必要な最小限に絞る。画面から取る情報と、計算で出す情報を分ける。

| 情報 | 取り方 |
|---|---|
| 出目(2〜12) | 黄色の表示「X rolled N」の数字をテンプレートで読む(この計画の中心) |
| 止まったマス | 前の位置 + 出目の計算。カードの移動・刑務所の場合は、Log の行で補う |
| 支払い・受け取りの額 | 所持金の差分(計画 1)。額は Log から読まない |
| 購入・オークションの結果 | 画面の種類(`screens.py`)と、自分の操作の結果から分かる。AI の購入・落札は、Log の行で読む |
| カード・刑務所の出来事 | Log の行で読む(既知の文型だけ) |

黄色の表示と、Log の行のどちらが安定して読めるかを、先に画像で確かめる。確かめられない情報は、不明として状態追跡(計画 3)へ渡す。

## 実装対象の機能

### 1. 出目の読み取り(`vision/dice.py`)
- 黄色の表示の領域から、プレイヤー名(自分 / AI)と出目 N(2〜12)を読む。ゾロ目の表示があれば、その有無も読む
- 表示が出ていない画面では「なし」を返す(不明と区別する)

### 2. Log の行の読み取り(`vision/log_reader.py`)
- Log パネルが開いている画面から、行を切り出し、既知の文型に照合してイベントにする
- 文型は、集めた実機の Log から決める(出目、止まったマス、カードの引き、刑務所、購入、落札など)
- 語彙は閉じた集合: プレイヤー名、40 マスの名前、カードの文面、固定の動詞。集合に無い語は「不明」

### 3. 出来事への変換
- 読み取り結果を、`logic` が扱う出来事(`Rolled`、`DrewCard`、`SentToJail`、`BoughtBy` など)に変換する

## 受け入れ条件

### 出目
- [ ] 評価セットで、プレイヤー名と出目の誤読が 0 件
- [ ] 表示が無い画面で、出目を返さない(「なし」)
- [ ] 不明は許容するが、表示のある画像の 10% 以下

### Log の行
- [ ] 評価セットの行で、文型と値の誤読が 0 件(不明は許容)
- [ ] 切れた行・透けで読めない行は「不明」を返す
- [ ] 同じ画面を 2 回読んで一致する

### 共通
- [ ] 評価に使う画像は、テンプレートの切り出し元と別の局のものにする
- [ ] `logic/` が `vision/` を import しない(`lint-imports`)

## 成功指標

- 誤読 0
- 1 手番の出目の取得率: 手番の進行中に、黄色の表示が出る時間内に読めること(評価で、表示の出ている時間と取得間隔を測る)

## 前提・仮定

- 黄色の表示の位置は、AI の手番の例で端末座標 x 1012〜1503、y 212〜290(`20261101-monopoly-vision/03_TASKLIST.md` の検証メモ)。自分の手番の出目の表示位置・有無は未確認 — 根拠: 検証した画像が `ai_turn57.png` だけ
- ゾロ目の連続、刑務所からの脱出は、Log の行または画面(JAIL ダイアログ)で補う — 根拠: RULES.md の刑務所の実機確認
- Log の行の語彙は、収集した画像の範囲で作る。語彙に無い行は不明とし、増やす余地を残す — 根拠: カードの文面の全件は未収集(RULES.md「ほかのカードも、引いたときに確かめる」)

## スコープ外

- 所持金の読み取り(計画 1)
- 盤上の駒の位置の画像認識(出目からの計算で追う)
- 実機の操作、状態追跡、プラグイン登録(計画 3)
- OCR・VLM の導入(テンプレート照合で受け入れ条件を満たせない場合の、別計画)
