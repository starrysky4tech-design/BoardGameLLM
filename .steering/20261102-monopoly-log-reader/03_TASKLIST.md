## タスク完了の原則

このファイルは作業の正式な進捗記録である。全タスクが `[x]` になるまで作業を続ける。

### 進捗記録の規則
- タスクは完了した直後に、1件ずつ `[x]` にする(まとめて更新すると、中断時に未実装のタスクが完了扱いで残るため)
- タスクを残してよいのは、下記「タスクスキップが許可される唯一のケース」に該当する場合だけ。「時間の都合」「複雑すぎる」「後回し」はスキップの理由にならない
- 未完了タスク(`[ ]`)が残っている状態で、作業を終了しない

### 実装可能なタスクのみを計画
- 計画段階で「実装可能なタスク」のみをリストアップ
- 「将来やるかもしれないタスク」は含めない
- 「検討中のタスク」は含めない

### タスクスキップが許可される唯一のケース
以下の技術的理由に該当する場合のみスキップ可能:
- 実装方針の変更により、機能自体が不要になった
- アーキテクチャ変更により、別の実装方法に置き換わった
- 依存関係の変更により、タスクが実行不可能になった

スキップ時は必ず理由を明記:
```markdown
- [x] ~~タスク名~~(実装方針変更により不要: 具体的な技術的理由)
```

### タスクが大きすぎる場合
- タスクを小さなサブタスクに分割
- 分割したサブタスクをこのファイルに追加
- サブタスクを1つずつ完了させる

## フェーズ1: 画像を集める

- [ ] 集める前に、ユーザーに対局の状態を確認する(新しい対局を始めると戦績が変わる操作のため)
- [ ] 実機で、読み取り専用(`adb -s 355092380222016 exec-out screencap -p`)で画像を集める
  - [ ] 黄色の表示(出目): 自分の手番・AI の手番・ゾロ目・刑務所の最中。表示が出る時間を測るため、0.2 秒間隔の連続取得も 1 手番分行う
  - [ ] Log パネル: 開いた状態を、局の進行に合わせて 100 枚以上(出目、カード、刑務所、購入、落札の行を含める)
  - [ ] 局 A(語彙の切り出し用)と局 B(評価専用)に分ける
  - [ ] 置き場: `datasets/eval/monopoly/log/A/`、`.../B/`(Git 管理外)
- [ ] 各画像の正解を、画面を見て手で付ける(`labels.json`: 黄色の表示の有無・プレイヤー・出目、Log の各行の文)

## フェーズ2: 観察と読み方の決定

- [x] 黄色の表示を観察する(位置、色の条件、表示される時間、自分の手番での有無、ゾロ目の表示)。結果: `OBSERVATIONS.md`。表示はカメラが止まった後だけ出て、撮影の速度(1.1〜1.5 秒)では確実に撮れなかった
- [ ] Log パネルの文字を観察する(文字の色、縁、行の高さ、新しい行の位置)。輝度の閾値以外の分け方(色・縁)で、行を分離できるか確かめる
- [ ] 数字の字体が、計画 1 の `digits/` と同じかを確かめる
- [ ] 観察結果と、読み方の決定(出目は黄色の表示だけで取るか、Log の行で補うか)を `OBSERVATIONS.md` に書く
- [ ] Log の文型の一覧を、集めた行から確定する(収集した行の文を一覧にし、文型にまとめる)

## フェーズ3: 出目の読み取り

- [ ] `logic/events.py` に出来事の型(`Rolled` など)を定義する(画面に依存しない)
- [ ] 数字・プレイヤー名のテンプレートを切り出す(局 A から)
- [ ] `vision/dice.py` を作る
  - [ ] 黄色の画素の抜き出しと連結成分への分割
  - [ ] プレイヤー名の照合、数字の読み取り(2〜12 の範囲検査)
  - [ ] 「なし」と「不明」の区別
- [ ] ユニットテスト `test_dice.py` を書く(合成画像: 通常、桁の違い、範囲外 → 不明、表示なし → なし。期待値は手で書く)
- [ ] 局 B で評価し、結果を `RESULT.md` に書く(受け入れ条件: 誤読 0、不明 10% 以下)
- [ ] 連続取得の画像で、表示が出ている間に読めること(取りこぼさない取得間隔)を確かめる

## フェーズ4: Log の行の読み取り

- [ ] 語彙のテンプレート(プレイヤー名、動詞、マス名、カードの文面)を局 A から切り出して `data/words/` に置く
- [ ] `vision/log_reader.py` を作る
  - [ ] 行の切り出し(フェーズ 2 で決めた色・縁の条件)
  - [ ] 単語への分割と、語彙への照合
  - [ ] 文型への照合とイベント化。語彙・文型に無いものは不明
  - [ ] 切れた行は不明
- [ ] ユニットテスト `test_log_reader.py` を書く(合成画像: 各文型、語彙外、切れた行。期待値は手で書く)
- [ ] 局 B で評価し、結果を `RESULT.md` に書く(受け入れ条件: 誤読 0。不明の割合と、不明の原因別の内訳を記録)
- [ ] 同じ画面を 2 回読んで一致することを確認する
- [ ] 不明の行の画像を保存する仕組み(語彙を増やす入力)を作る

## フェーズ5: 品質チェックと修正
