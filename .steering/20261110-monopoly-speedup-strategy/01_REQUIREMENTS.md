# 要求内容

## 概要

Monopoly の自動実行について、状態(所有・位置・所持金・出目)の最新化にかかる時間と回数を減らし、あわせて方針(建設の時機、競りで安く買う、相手の所持金を削る)を強化する。

## 背景

3 局目(2026-11-10、`scripts/run_game3_d.log`)までの実行で、次の問題が分かっている。

| 問題 | 現状(コードと実行ログから) |
|---|---|
| 所有の確認が遅い | `vision/holdings.read_all_holdings` は、色グループ 8 つを順に拡大盤で開いて読む。1 回 約 130 秒。現金の食い違い・Log の取りこぼしのたびに走る(3 局目 d ログで 4 回) |
| 家・ホテルの軒数の確認が遅い | 軒数は、色グループごとに拡大盤(独占の色は建設画面)を開いて読む。所有の確認と同じ巡回の中で、8 グループ全部を開く。隣の色の画面の端に写る土地は軒数を誤る(`holdings.merge_view` の注記) |
| 抵当を画面から読めない | 拡大盤の棒と家からは分からず、保存の値を引き継いでいる。食い違うと操作が失敗する |
| Log の読み取りが多い | 操作(Roll、End Turn、カードを閉じる、購入、入札…)のたびに、Log を開いて 3 ページ読む(1 回 約 15 秒)。1 手番で 2〜4 回 |
| AI の現金が読めないことがある | 画面の値が `None` になる回がある(d ログ: `'ai': None`)。照合が片側だけになる |
| 出目が取れないことがある | Roll の後にカード・購入画面が割り込むと、出目を読めないまま進む(「結果の表示が割り込んだ」)。Roll の前後の待ちも長い(静止の確認 2 回 + 待ち 3 秒) |
| 建設の時機が粗い | 「相手が色グループの入口の手前 7 マス以内」だけで決める(暫定値)。建てるのは自分の Roll の前で、Roll の後の支払いで現金が減る前に建設費を使ってしまう。相手が止まる確率、賃料の増分、収監中かどうかを見ていない |
| 競りを安く買う手段が 1 つだけ | 「相手が定価を払えないなら見送る」だけ。相手の入札の上限(難易度ごとの傾向)を使っていない |
| 相手に払わせる入札が弱い | `raising_bid` は、自分の上限(価値と残す現金)までしか上げない。自分が欲しくない・買えない土地では、すぐ降りて、相手に安く取らせる |

**手がかり(今回の調査)**: 全体盤(通常の盤の画面)の 1 枚に、4 辺すべての所有の棒(青 = 自分、黄 = AI)と、抵当の印(マスの上の赤い「M」)が写っている(`datasets/eval/monopoly/screens/my_turn_end_turn.png`、`after_auto_sell.png`)。いまは下辺の 6 か所(`bars.VIEWS["global_bottom"]`)しか使っていない。

## 実装対象の機能

### 1. 全体盤 1 枚からの所有・抵当の読み取り

- 通常の盤の画面 1 枚(タップなし)から、28 か所の所有者(自分・AI・無所有)と抵当の有無を読む
- 手番ごとに、台帳(Log から更新した状態)と全体盤の読みを照合し、所有の食い違いは、その土地だけを直す(全体の読み直しをしない)
- 再同期の所有・抵当の部分は「全体盤 1 枚」に置き換える

### 1b. 家・ホテルの軒数(自分・AI)の確認の回数削減と短縮

- 通常時は、画面を開かずに軒数を保つ: 自分の建設・売却は操作の結果で、AI の建設・売却は Log の行(`built N house(s) on`、`built a hotel on`、売却)で台帳を更新する
- 全体盤の 1 枚から軒数を読めるかを、実機の画像で先に確かめる(マスの上の家・ホテルの絵)。読めるなら、手番ごとの照合(タップなし)に使う。読めない・不確かなら、全体盤は「家がある / 無い」の検知までに留める
- 画面を開いて読むのは、次の場合だけにする: (a) 再同期のとき、独占が成立している色グループだけ(家が建つのは独占の色だけ。自分の独占は建設画面、AI の独占は拡大盤)、(b) 台帳と全体盤の検知が食い違った色グループだけ
- 独占が 1 つも無い局面では、軒数の確認のために画面を開かない(全て 0 軒と確定できる)
- 軒数は、その色グループ自身の画面の読みだけを採る(隣の色の画面の端の読みは使わない)

### 2. 位置の最新化の回数を減らす

- 自分の位置は、出目(画面)で進め、Log の「landed on」で確かめる
- Log を読むのは、原則として 1 手番の周回に 1 回(AI の手番が終わり、自分の Roll の画面に戻ったとき)と、位置・現金の照合が合わないときだけにする
- Log は 1 ページずつ読み、前回の読みとつながった時点で打ち切る(固定の 3 ページをやめる)

### 3. 所持金の読み取りの安定化

- 全体盤の 1 枚から、所持金・所有・抵当・出目を、同じ取得画像で読む(取得を共有する)
- AI の所持金が読めないときは、取り直して再度読む。それでも読めなければ、不明のまま扱う(推測で埋めない)

### 4. 出目の把握の改善

- 出目は「画面の読み取り」と「Log の `rolled N`」の 2 系統で取り、片方が欠けても、その手番の出目(合計とダブル)を確定する
- カード・購入画面が割り込んだときは、閉じた後に読み直す。読めなければ Log の行で補う
- Roll の前後の待ち(静止の確認、反映の確認)を、実測に基づいて短くする

### 5. 建設の時機の改善

- 建てる判断を「相手が次の手番で、その色グループに止まる確率 × 賃料の増分」と建設費の比較に変える(ダブルの振り直し、収監中を考慮する)
- 建てる時点を、自分の手番の終わり(End Turn の直前)に移す。Roll の後の支払いを終えた現金で判断する
- ホテルまで建てる基準(現金の閾値だけで決めている `_target_houses`)を、同じ期待値の比較に揃える
- 相手の現在位置が分からない(追跡が外れている)ときは、建てない

### 6. 競りで定価より安く買う戦略

- 購入画面で、定価で買うより競りの方が安く取れる見込みが高いとき、見送って競りに回す
- 見込みは、相手の入札の上限の推定(相手の現金、難易度ごとの入札の傾向)から出す。傾向は、これまでの対局の記録(`events_game2_easy_final.log`、`events_game3_veryeasy.log`)から決め、出典を残す
- 取られると困る土地(独占の完成・阻止、妨害価値が高い)は、競りに回さず定価で買う

### 7. 相手に高く買わせる戦略

- 自分が買わない・買えない土地の競りで、相手の入札の上限の推定の手前まで、入札を重ねて価格を上げる
- 誤って落札したときの損(入札額 − 自分にとっての価値)に上限を置く。自分の現金を超える入札はしない
- 相手が降りて落札になった場合に備え、落札後の現金が「残す現金」を割らない範囲で行う

## 受け入れ条件

### 1. 全体盤 1 枚からの所有・抵当の読み取り
- [ ] 評価画像(`datasets/eval/monopoly/screens/` の盤の画面)で、28 か所の所有者を全て正しく読む(正解は画像を見て手で作る)
- [ ] 抵当の印がある画像(`after_auto_sell.png` など)で、抵当の有無を全て正しく読む
- [ ] 読めない土地(駒が棒に重なる、色補正)は、不明を返す(既定値で埋めない)
- [ ] 実機で、AI の競りの落札(価格が Log から読めない場合)の後、全体の読み直しなしで、所有が正しく更新される

### 1b. 家・ホテルの軒数
- [ ] 全体盤から軒数を読めるかの確認結果(読める範囲、読めない条件)を、実機の画像つきで `RESULT.md` に残す
- [ ] 単体テスト: 独占が無い状態の再同期は、拡大盤を 1 つも開かない。独占が k 色なら、開くのは k 色だけ
- [ ] 単体テスト: AI の建設・ホテル・売却の Log の行で、台帳の軒数が更新される
- [ ] 評価画像(`improvements_*.png`、拡大盤の画像)で、自分・AI の軒数とホテルを正しく読む(既存の読み取りの回帰)
- [ ] 実機で、再同期が「10 秒 + 独占の色の数 × 10 秒」以内に終わる(現状 約 130 秒。独占 2 色なら 30 秒以内)
- [ ] 実機で、自分・AI の建設の後、画面を開かずに台帳の軒数が合っている(次の再同期、または目視の建設画面と一致)

### 2. 位置の最新化
- [ ] 通常の手番(割り込みなし)で、Log を開く回数が、1 手番の周回につき 1 回になる
- [ ] 前回の読みとつながる場合、読むページ数が必要最小限になる(単体テスト: 1 ページでつながれば 1 ページで終わる)
- [ ] 位置の食い違い(出目の計算と「landed on」)は、これまでどおり検出して止まる・直す

### 3. 所持金
- [ ] 実機の 50 手以上の実行で、AI の所持金が不明のまま照合に進む回数が 0 回(取り直しで読める)。読めない場合は、その旨が記録に残る

### 4. 出目
- [ ] 実機の 30 回以上の Roll で、出目(合計とダブル)が確定しない回数が 0 回
- [ ] Roll の 1 回あたりの所要時間(Roll の画面を見てから、出目が確定するまで)が、現状より短い(現状の実測を先に取る)

### 5. 建設の時機
- [ ] 判断の式と定数の根拠を `docs/02`「Monopoly の判断」に書く
- [ ] 単体テスト: 相手が止まる確率が高い位置では建て、低い位置・収監中・位置不明では建てない
- [ ] シミュレーション(`logic/simulation.py`)で、現行の方針(入口の手前 7 マス)に対する勝率が下がらない

### 6. 競りで安く買う
- [ ] 単体テスト: 相手の上限の推定が定価を下回る土地は見送り、独占に関わる土地は定価で買う
- [ ] 相手の入札の傾向の値に、出典(記録のファイルと行)が付いている
- [ ] 購入画面の判断と競りの上限が、同じ価値(`deed_value`)から出ている(既存の原則を崩さない)

### 7. 相手に高く買わせる
- [ ] 単体テスト: 自分が買わない土地で、相手の上限の推定の手前まで入札が上がる。損の上限と現金を超えない
- [ ] 実機で、入札額が画面の自分の現金を超えない(既存の停止条件を維持する)

### 共通
- [ ] `.\scripts\check.ps1` が通る(ruff、mypy、import-linter、pytest)
- [ ] `logic/` から `vision` を import しない

## 成功指標

- 再同期 1 回: 約 130 秒 → 「10 秒 + 独占の色の数 × 10 秒」以内(独占なしなら 10 秒以内)
- 軒数の確認のために画面を開く回数: 通常の手番では 0 回
- 1 手番の周回(自分の Roll 〜 次の自分の Roll)の、状態の最新化に使う時間: 現状の実測の半分以下(現状の実測は、設計の前に d ログと実機から取る)
- 実機で 100 手以上、人の介入なしで止まらずに進む(3 局目の続き)

## 前提・仮定

- 全体盤の 4 辺の棒と抵当の印は、常に同じ位置に出る — 根拠: 評価画像 2 枚(卓の背景が違う 2 局)で同じ位置。実機での確認は、実装の最初に行う
- 家が建つのは独占の色グループだけなので、家の読み取りは独占の色に限ってよい — 根拠: ルール(`RULES.md`)
- 全体盤のマスの上の家・ホテルの絵から、軒数まで読めるかは未確認(絵が小さい)。読めない場合でも、Log と操作の結果による台帳 + 独占の色だけの読み直しで、要求(回数削減・短縮)は満たせる — 根拠: 評価画像では家が建った全体盤の画像が無く、実機で確かめる必要がある
- AI の建設・売却は、Log の行で漏れなく分かる — 根拠: `COORDINATES.md`「Log の文型」(`built a hotel on` など)。OCR の崩れによる読み落としは、現金の照合(建設費ぶんの差)と全体盤の検知で見つける
- 駒の位置を画像から読むことは、今回は行わない — 根拠: 駒は対局ごとに違い(Top Hat、Shoe、Dog、Thimble、Wheelbarrow)、金属色で盤に紛れる。出目と Log の 2 系統で足りる
- 相手の入札の傾向は、難易度(Very Easy、Easy)ごとに違う — 根拠: `05_HANDOFF_20261108.md` の観察(Easy は定価を超えて競る、Very Easy は現金の範囲で入札)。記録の件数が少ない難易度は、保守的な値(相手は現金の全額まで入札する)にする
- 実機の確認は、保存してある 3 局目(Very Easy)の続きで行う。対局の進行は確認なしで進めてよい — 根拠: ユーザー指示(2026-11-10、`06_HANDOFF_20261110.md`)
- 建設の時機の既存の指示(入口の手前 7 マス、暫定)は、今回の期待値の基準で置き換えてよい — 根拠: 今回の依頼「敵の現在位置を見て、家・ホテルを建てて収益増を目指す」

## スコープ外

以下はこのフェーズでは実装しません:

- 駒の位置の画像認識
- 取引の対案を実機で出す操作、取引画面のヒント吹き出しの対処(`06_HANDOFF_20261110.md` の残り 1)
- 刑務所の基準の見直し、緑の建設の確定、家の在庫不足
- `GamePlugin` の形への移行(`runtime.py` と `run_agent.py` の構成の整理は、今回触る範囲に限る)
- 3 人以上の対局
