# 要求内容

## 概要

Monopoly の画面認識を、本番の自律対局で使える形にする。優先度1は「画面の種類の判別」、優先度2は「出目と着地(と支払い)の読み取り」。どちらも `bglm run --game monopoly` から Python だけで使えることを目標とする。

## 背景

- 現状の Monopoly は `logic/`(ルールと思考)のみ。画面認識・操作・プラグイン登録は無い
- 実機対局では、Claude が画面を見て手で判断していた。本番は Python のみで回すため、画面の状態と出来事を機械的に得る必要がある
- 2026-11-01 の対局で、画面の見落とし(支払い、拡大表示、オークションの状態)と、Log の読み違えが起きた
- Phase 0 で、所持金の数字と Log の行切り出しは、テンプレート・OCR では不安定だった(RESULT.md)。本計画では、所持金は対象外。出目と着地だけを対象にする

## 実装対象の機能

### 1. 画面の種類の判別(優先度1)
- 現在の画面が、次のどれかを判別する: 自分の Roll 待ち / End Turn 待ち / 購入確認 / オークション / 取引 / カード表示 / 収監(Post Bail・Use Card・Roll) / 管理(Manage、拡大盤) / Log 表示 / Pause / AI の手番 / 不明
- 判別できないときは「不明」を返す。推測で別の画面にしない
- 判別結果に信頼度を付ける(閾値未満は「不明」扱い)

### 2. 出目と着地の読み取り(優先度2)
- 自分と AI の出目(2〜12)を読む
- 止まったマス名(または盤上の位置の番号)を読む
- 支払い・受け取りの額と相手を読む(Log の文を、既知の文型で照合する)
- 読めなかった項目は「不明」として扱い、値を埋めない

## 受け取り条件

### 1. 画面の種類の判別
- [ ] 参照画像(2026-11-01 の対局のスクリーンショット)の全種類で、正しい画面名を返す
- [ ] 判別できない画面(拡大盤の途中、アニメーション中)は「不明」を返す
- [ ] `logic/` が `vision/` を import しない(import-linter)

### 2. 出目と着地の読み取り
- [ ] Log の参照行(出目、着地、支払い)で、正しい値を返す
- [ ] 読めない行は「不明」を返す(誤った値を返さない)
- [ ] 読み取り結果が、同じ画面を2回読んで一致する(揺らがない)

## 成功指標

- 画面判別: 参照画像の正答率 100%、誤判別 0(不明は許容)
- 出目・着地: 参照行の正答率 100%、誤読 0(不明は許容)
- 本番で、判別できない画面に当たったら停止して記録する(推測で操作しない)

## 前提・仮定

- 画面の位置・色は、2432x1080 の実機解像度で固定。根拠: Kahuna の `screens.py`(座標は原寸)と RESULT.md(SHG11 の横向き 2432x1080)
- 本番の判断は Python の policy が行い、Claude は介入しない。根拠: `memory/monopoly-operating-model.md` と本作業の指示
- 所持金の自動読み取りは本計画の対象外(Phase 0 の結論)。根拠: RESULT.md「文字の機械読み取り … 不安定」
- 認識の精度評価は、実機の録画(評価セット)で行う。評価セットは Git 管理しない。根拠: docs/05「認識のテスト」

## スコープ外

- 所持金の数字の自動読み取り(Phase 0 で不安定と判明。別計画で扱う)
- 盤上の駒位置の画像認識(出目と着地の読み取りから内部で追う)
- 取引・建設・抵当の操作(executor)。本計画は認識まで。操作は次の計画
- 思考ロジックの変更(`logic/` は変更しない)
- VLM の利用(本計画の読み取りは、テンプレートマッチングのみ)
