## タスク完了の原則

このファイルは作業の正式な進捗記録である。全タスクが `[x]` になるまで作業を続ける。

### 進捗記録の規則
- タスクは完了した直後に、1件ずつ `[x]` にする（まとめて更新すると、中断時に未実装のタスクが完了扱いで残るため）
- タスクを残してよいのは、下記「タスクスキップが許可される唯一のケース」に該当する場合だけ。「時間の都合」「複雑すぎる」「後回し」はスキップの理由にならない
- 未完了タスク（`[ ]`）が残っている状態で、作業を終了しない

### 実装可能なタスクのみを計画
- 計画段階で「実装可能なタスク」のみをリストアップ
- 「将来やるかもしれないタスク」は含めない
- 「検討中のタスク」は含めない

### タスクスキップが許可される唯一のケース
以下の技術的理由に該当する場合のみスキップ可能:
- 実装方針の変更により、機能自体が不要になった
- アーキテクチャ変更により、別の実装方法に置き換わった
- 依存関係の変更により、タスクが実行不可能になった

スキップ時は必ず理由を明記:
```markdown
- [x] ~~タスク名~~（実装方針変更により不要: 具体的な技術的理由）
```

### タスクが大きすぎる場合
- タスクを小さなサブタスクに分割
- 分割したサブタスクをこのファイルに追加
- サブタスクを1つずつ完了させる

### 計画と実績の差分

**計画と異なった点**:
- Kahunaの決算・カフナコマ・終了画面、大戦略SSB2の戦果予測画面、スキップ設定の効果は、1ゲームを手で遊ぶ必要があるため、ユーザー承認で Phase 1・3・4 の自動プレイのログに移した
- 結果の保存先を `datasets/`（Git管理外）から `.steering/` の `RESULT.md` に変更した
- 検証マップは「最も低難度の2勢力マップ」から、ユーザー指定の「ハロー・大戦略」に確定した（先頭約20個のシナリオマップは別ルール）

**新たに必要になったタスク**:
- PrintWindow による取得、前面化の再試行、クリックの待機、ホイール操作（実機で動かすために必要になった）
- pywin32 の型スタブ追加と、型を持たない `pydirectinput` の mypy 設定

**技術的理由でスキップしたタスク**（該当する場合のみ）:
- 上記の「計画と異なった点」の画面撮影とスキップ設定の計測（ユーザー承認の計画変更で後続フェーズへ移動）
- (仮)の数値の置き換え（認識・思考が未実装で測れないため。画面取得時間とGPUメモリのみ反映）

**注**: ここに記載するのは技術的理由によるスキップだけである。「時間の都合」「難しい」は該当しないため、そうしたタスクはスキップせずに完了させる。

### 学んだこと

**技術的な学び**:
- `adb input` の座標系は端末で異なり、SHG11は回転後の画像座標をそのまま受ける。縦向きのホーム画面のタップは両方の座標系で一致するため、縦向きの成功は判定にならない
- ゲームが即時クリックを無視することがある。ハイライトが動いても押下が届いたとは限らず、画面差分で確認する
- PrintWindow は隠れたウィンドウを取得でき、mss より速い。mss は上のウィンドウが写る
- 4GBのGPUはデスクトップだけで約1.17GB使われ、実質2.9GB。ゲーム＋2BのVLMは載るが余裕は小さい
- VLMは題名や価格は読めるが、密な数字の表や重なったカードの数え上げは誤る

**プロセス上の改善点**:
- 画面の配置は、1枚の画像から推測せず、操作して確かめてから `docs/` に書く（手札と場札を取り違えて、記述を直す手戻りがあった）
- 実機の操作は、1手ごとに画面を確認する。ユーザーのアカウントに影響する操作は事前に確認する
